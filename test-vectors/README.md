# Тестовые векторы

Любая реализация клиента или сервера Veil v1 обязана проходить все векторы из этой папки.

| Файл | Что проверяет | Кто генерирует |
|---|---|---|
| `rfc9497-poprf-ristretto255-sha512.json` | RFC 9497 Appendix A.1.3 (POPRF): Blind, Evaluate, доказательство, Finalize | копия из RFC |
| `veil-v1.json` | JCS и строгий JSON, base64url, 12 слов → корень и медленная метка (Argon2id), цепочка «корень → устройство → ключ шифрования» (`device`: байты сообщений, подписи, 5 подделок), `post_pk`, `text_sha256`, конверт (подпись ключом устройства, расшифровка, 6 случаев отказа с кодами), ответ сервера, ники (в том числе невидимые заполнители), ключи похожести ников (`nick_key`: какие ники совпадают по UTS #39), многочастный ответ (`response_parts`), скрытое (`hidden_all` с `callback_data`, `hidden_to`, `hidden_reject`), выдача токенов (`issue_cross_request`: детерминированный `VEILREQ` на два дня одним ключом `t1`; `issue_reject`: 9 некорректных запросов), константы протокола (`limits`), коды ошибок ответа (`error_codes`) и форматы идентификаторов (`formats.kid`) — один список на обе реализации; маркет плагинов (`market`, spec/10): подписанный индекс, зашифрованный пакет `VEILPKG1`, запрос лицензии `VEILLIC`, сообщения сертификата активации и подписи установки | `veil-client`: `python -m tools.gen_vectors` |
| `reference.json` | **официальные векторы внешних стандартов**, перенесены без изменений: BIP-39 Trezor (12 слов, seed с паролем «TREZOR»), HKDF-SHA256 RFC 5869 A.1–A.3, JCS RFC 8785 (тестовые данные cyberphone; наборы с дробными числами — как отказ строгого JSON) | вручную из источников, указанных в файле; не генерируется |
| `poprf-cross.json` | эмитент сервера проекта (независимая реализация) оценил ослеплённые элементы из `veil-v1.json` (`poprf_cross_request`); клиент обязан принять доказательство и получить те же `outputs` | сервер проекта |
| `license-cross.json` | бот-магазин сервера проекта ответил на запрос лицензии из `veil-v1.json` (`market.license`) сообщением `VEILLICRES`; клиент обязан проверить доказательство и получить тот же `output` | сервер проекта |
| `issue-cross.json` | эмитент сервера проекта ответил на `issue_cross_request` сообщениями `VEILRES` (второй день выдан частично: 1 из 2); клиент обязан проверить доказательства и получить те же `outputs` | сервер проекта |

Шифртексты sealed box (`sealed`) случайны по построению и меняются при каждой генерации; проверяется
только расшифровка и результат.

Порядок обновления: `gen_vectors` (клиент) → `scripts/sync-vectors.sh` и запись `poprf-cross.json`, `issue-cross.json`,
`license-cross.json`
(сервер) → тесты обеих сторон.
