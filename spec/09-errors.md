# 09. Ошибки

Ответ сервера (`VEIL1R`, зашифрован на `resp_pk`):
```json
{"v":1,"re":"<envelope.id>","ok":false,"error":{"code":"E_TOO_LONG","overflow":214},"sig":"<b64url>"}
{"v":1,"re":"<envelope.id>","ok":true,"result":{"n":246,"url":"https://t.me/..."},"sig":"<b64url>"}
```
`overflow` и `retry_after` присутствуют только когда относятся к ошибке (`retry_after` — у `E_RATE`
и `E_NICK_COOLDOWN`). `sig` — подпись `server_sig` (04).
Токен записывается в потраченные **только при успешном выполнении операции**, в одной транзакции
с её результатом. При любой ошибке клиент может использовать тот же токен повторно (если день не сменился).
Повтор того же конверта после сбоя не тратит токен второй раз и не выполняет действие второй раз (03, 05).

Повтор конверта с тем же `id` получает сохранённый ответ (04), кроме ошибок `E_INTERNAL`, `E_RATE`,
`E_TELEGRAM`, `E_PENDING`: они не сохраняются, и повтор с тем же `id` выполняется заново. `E_UNCONFIRMED` сохраняется:
повтор не публикует пост второй раз. Список кодов — общий вектор `error_codes` в `test-vectors/veil-v1.json`. Пока первая копия
операции выполняется, повтор остаётся без ответа (ответ придёт на первый конверт).

| Код | Когда | Что делает клиент |
|---|---|---|
| `E_VERSION` | неподдерживаемая `v` | сообщить владельцу «обновите бот», ссылка на релиз |
| `E_MALFORMED` | нарушен формат (04, «Строгий JSON»), неизвестное поле, несовпадение `kid` | ошибка в клиенте, показать владельцу |
| `E_NOT_ENVELOPE` | пришло не `VEIL1` | ничего |
| `E_DECRYPT` | не расшифровать (старый `kid`?) | обновить `keys.json`, повторить один раз |
| `E_SIG` | подпись неверна | ошибка в клиенте, показать владельцу |
| `E_CLOCK` | `ts` вне ±300 с | проверить время на сервере бота |
| `E_REPLAY` | повтор `id`; или тот же `id`, но другое действие или другой пост (05, «Однократность») | ничего (это дубль) |
| `E_TOKEN_MISSING` / `E_TOKEN_INVALID` / `E_TOKEN_SPENT` / `E_TOKEN_DAY` | проблема с токеном | взять другой токен; если кончились — предложить пополнить |
| `E_TOKEN_INVALID` / `E_TOKEN_SPENT` для `market.*` | лицензия не от магазина или неверный сертификат; лицензия активирована другой установкой (10) | показать владельцу; лицензию не удалять |
| `E_RATE` | слишком часто | ждать `retry_after` |
| `E_BOT_NOT_BOUND` | личность привязана к другому боту | объяснить: перенос на этот бот — `restore` (12 слов) на машине бота |
| `E_DEVICE` | ключ устройства неизвестен серверу или отозван (02) | есть свой сертификат — повторить `device.set`; получили `E_STALE` — сообщить, что личность восстановлена на другом устройстве |
| `E_STALE` | сертификат устройства или ключ шифрования старее зарегистрированного | сообщить владельцу: личность перенесена на другое устройство по 12 словам |
| `E_CONTENT_MISMATCH` | контент не совпал с конвертом | переотправить операцию целиком |
| `E_UNSUPPORTED` | тип контента не поддерживается; для `market.*` — маркет на сервере не настроен (10) | показать владельцу |
| `E_TOO_LONG` | текст не помещается; `overflow` = на сколько | показать «сократите на N символов» |
| `E_NOT_FOUND` | нет поста `n`; для `market.*` — плагин не платный или нет ключа этой версии (10) | показать владельцу |
| `E_NOT_OWNER` | подпись не ключом этого поста | показать владельцу |
| `E_EDIT_WINDOW` / `E_EDIT_LIMIT` | правка позже 24 ч или больше 5 раз | показать владельцу |
| `E_NICK_INVALID` / `E_NICK_COOLDOWN` | ник не прошёл проверку или менять рано | показать владельцу |
| `E_NICK_TAKEN` | пара ник·метка занята (с точностью до похожих букв, 02) | предложить другой ник |
| `E_TELEGRAM` | Telegram отказал после всех повторов | показать владельцу; токен не потрачен |
| `E_UNCONFIRMED` | запрос публикации ушёл в Telegram, ответа нет (обрыв, таймаут, 5xx): пост мог выйти, сервер не повторяет | сказать владельцу проверить группу и, если поста нет, отправить снова; токен не потрачен |
| `E_PENDING` | операция принята, но ещё не завершилась (пост ждёт в очереди публикации дольше 100 с) | через `retry_after` повторить **тот же** конверт: тот же `id`, тот же токен, тот же `resp_pk`, новый `ts`. Сервер вернёт итог, действие второй раз не выполнится. Токен потрачен вместе с действием; секрет поста не терять. Любая поздняя ошибка повтора этого конверта (например, `E_TOKEN_DAY` после полуночи у старого сервера) не повод собирать новый конверт |
| `E_INTERNAL` | ошибка сервера | повторить позже |
| `E_RATE` от занятого сервера | все обработчики заняты (конверт не принят в работу) | ждать `retry_after`, токен не потрачен |

Ответы об ошибках, которые сервер даёт до выполнения операции (подпись, время, `auth`, «занято»), уходят из очереди
отправки и не чаще раза в 3 с на чат; при переполнении очереди ответ отбрасывается. Клиент, не получивший ответа,
повторяет тот же конверт (04) — так ферма ботов с чужими подписями не останавливает приём конвертов.
