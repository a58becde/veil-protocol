# 06. Как пост выглядит в группе

## Макет
```
Вася·7f3a9c                    ← ник·метка (жирный); у анонимного поста строки нет
№246  >>> №245               ← номер поста; ссылка на пост, на который отвечаем (если это ответ)

<текст пользователя со всем форматированием>

UPD: <дописанное>            ← секции append, по порядку
Ответы: > №247 > №250        ← ссылки на ответы (необязательная часть)
перейти в бота               ← ссылка на общий бот (необязательная, настраивается на сервере)
```
Даты и время в посте **нет**: Telegram сам показывает время сообщения (решение от 2026-10-14).

`№N` — сквозной номер поста в группе. Он нужен для сопоставления. Клиент, которому переслали пост, берёт номер
из шапки: строка `№N` (или `№N  >>> №M`) целиком — первая строка поста без подписи или вторая, если первая — ник·метка
жирным во всю строку. «№» в нике запрещён (02), а номер в тексте поста номером не считается: иначе ник «№1» или текст
подменяли бы номер, и ответ или удаление ушли бы на чужой пост (2026-10-19).

Все надписи («UPD:», «Ответы:», «Ответов:», «последний», «перейти в бота», «скрыто») берутся
из локали сервера `server/locales/<lang>.toml`.

## Части по приоритету
Сервер собирает сообщение из частей и проверяет длину **до** отправки в Telegram.

| Приоритет | Часть | Если не влезает |
|---|---|---|
| 1 | шапка (ник, `№N`, `>>> №M`) | всегда влезает (≤ 80 символов) |
| 2 | текст пользователя | create/edit отклоняются с `E_TOO_LONG` и `overflow` |
| 3 | секции UPD | входят в текст: правка отклоняется с `E_TOO_LONG` |
| 4 | полная строка ответов | заменяется на сокращённую |
| 5 | сокращённая строка `Ответов: 57 · последний > №312` | убирается |
| 6 | ссылка на общий бот | убирается первой из необязательных |

Порядок отбрасывания: 6, затем 4 → 5, затем 5.

Длина считается в **UTF-16 code units** по тем же правилам, что и `offset/length` у entities.
Лимит текста 4096, лимит подписи 1024. Для запаса резервируется 16 единиц.

## Совместимость с прошлым сообщением
Строка ответов перерисовывается при каждом новом ответе. Если пост был коротким, а после правки стал
длинным, при следующей перерисовке строка ответов автоматически сократится или пропадёт по таблице выше.
Ни одна перерисовка не может привести к ошибке Telegram «message is too long»: сервер проверяет длину заранее.
Если Telegram всё же вернёт ошибку длины (расхождение в подсчёте), сервер повторяет отправку без частей 4–6
и записывает инцидент в журнал (без номера поста).

## Обновление строки ответов
- Правка исходного поста при новом ответе ставится в очередь с **дебаунсом 30 секунд**: несколько
  ответов подряд дают одну правку.
- Ответ на пост без подписи (кружок, стикер, опрос) обновляет сообщение-шапку этого поста.
- Ответ на альбом обновляет подпись первого элемента.

## Сдвиг entities
Пользовательские entities сдвигаются на длину шапки (в UTF-16). Секции UPD добавляют свои entities
со своими смещениями. Пустые entities (length 0) отбрасываются. Это место нужно покрыть тестами
на суррогатные пары (эмодзи) и составные графемы.

## Ограничения Telegram, которые учитывает очередь
- Отправка в одну группу: не больше ~20 сообщений в минуту на бота. Правки тоже считаются.
- На `429` очередь ждёт `retry_after`, не теряя порядок.
- Пул публикующих ботов увеличивает пропускную способность. Править или удалять пост может только
  бот, который его отправил: `publisher_bot_id` хранится у поста.
