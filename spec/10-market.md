# 10. Маркет плагинов

Плагины бота пользователя (код, который реагирует на события бота) распространяются через каталог. Плагин может быть
бесплатным или платным; платный покупается за Telegram Stars. Здесь — форматы каталога, пакетов и лицензий и
операции сервера. Как бот запускает плагины (песочница, разрешения, манифест `plugin.toml`) — документ эталонного
клиента `veil-client/docs/MARKET.md`; протокол его не задаёт.

Требования:
- установить можно только пакет, который подписал автор и принял каталог;
- каталог не может подменить пакет автора, автор — выдать обновление от чужого имени;
- **покупка не раскрывает, в каком боте (и у какой личности) стоит плагин**: магазин знает покупателя, сервер —
  установку, связать их нельзя;
- платный пакет без лицензии не читается, даже если файл каталога общедоступен.

## Участники и ключи

| Ключ | У кого | Что подписывает |
|---|---|---|
| ключ каталога (Ed25519) | владелец каталога | индекс каталога |
| ключ автора (Ed25519) | автор плагина | свои сборки |
| ключ магазина (POPRF ristretto255-SHA512, `kid`) | сервер | лицензии (слепо) |
| `server_sig` (Ed25519, 02) | сервер | сертификаты активации |
| ключ установки `lic_pk` (Ed25519) | бот, на каждую лицензию | запросы ключей версий |
| ключ версии (32 байта) | сервер и владелец каталога | шифрует платный пакет одной версии |

Публичный ключ каталога клиент берёт из своей настройки (как `keys.json`, не из сети). Ключ магазина и его бот —
из подписанного индекса.

## Индекс каталога

Каталог — статические файлы по HTTPS (или `file://`): `index.json`, `index.json.sig`, `packages/<id>/<версия>.zip`
(бесплатный) или `packages/<id>/<версия>.zip.enc` (платный).

```
index.json = {
  "v": 1, "seq": <целое ≥ 1>, "generated": "ГГГГ-ММ-ДД",
  "shop": null | {"bot": "@имя_бота", "kid": "<kid>", "pk": "<base64url, 32 байта>"},
  "plugins": [Entry, ...],
  "revoked": [{"sha256": "<hex zip>", "reason": "<до 300 символов>"}, ...]
}
Entry = { "id", "name", "version", "description", "author", "author_pk", "license", "permissions", "network",
          "price_stars", "file", "sha256", "size", "zip_sha256", "encrypted", "author_sig", "reviewed" }
```
- Разбор строгий (04, «Строгий JSON»): неизвестные и недостающие поля — отказ всего индекса.
- `index.json.sig` = base64url(Ed25519(ключ каталога, `"veil/v1/market-index\n" ‖ байты index.json`)) — подпись
  **сырых байтов** файла, без канонизации.
- `seq` растёт с каждым изменением. Клиент и сервер **не принимают** индекс со `seq` меньше уже принятого: старый
  подписанный индекс (с отозванной сборкой или прежней ценой) подсунуть нельзя.
- `id` — `[a-z][a-z0-9_]{0,31}`, `version` — `X.Y.Z` (числа без ведущих нулей). Поля `name`…`price_stars`
  повторяют манифест пакета и должны с ним совпадать.
- `zip_sha256` — SHA-256 самого zip. `encrypted = (price_stars > 0)`. Бесплатный: `file` = `….zip`,
  `sha256 = zip_sha256`. Платный: `file` = `….zip.enc`, `sha256` и `size` — зашифрованного файла.
- `author_sig` = base64url(Ed25519(ключ автора, `"veil/v1/plugin\n" ‖ id "\n" version "\n" zip_sha256`)). Клиент
  проверяет её ключом `author_pk` из индекса; обновление с другим `author_pk`, чем у установленной версии, — отказ.
- `revoked` — по `zip_sha256`; отозванную сборку клиент не ставит, а установленную — останавливает и удаляет.

## Зашифрованный пакет

```
blob = "VEILPKG1" ‖ nonce[24] ‖ XChaCha20-Poly1305-IETF(key = ключ версии, aad = id "\n" version, zip)
```
Ключ версии — 32 случайных байта, свой у каждой версии: утечка одного раскрывает только эту версию. После
расшифровки клиент сверяет SHA-256 с `zip_sha256` и подпись автора.

## Лицензия

Лицензия — выход POPRF (RFC 9497, как токены, 03) на ключе магазина с публичным параметром
`info = "veil/v1/license/" ‖ id`: лицензия одного плагина не подходит к другому.

### 1. Запрос (бот)
Бот генерирует `input` (32 случайных байта), ослепляет его (`Blind`) и хранит `input`, `blind` до ответа. Владелец
переносит в бот-магазин одно сообщение:
```
VEILLIC <base64url(JCS {"v": 1, "plugin": id, "kid": kid магазина из индекса, "blinded": base64url(32)})>
```
Повторный запрос того же плагина до ответа ДОЛЖЕН давать то же сообщение (тот же `input`): оплата по первому
сообщению иначе не сошлась бы с сохранённым ослеплением.

### 2. Покупка (бот-магазин)
- Принимает сообщения только людей в личном чате. Пересылку с видимым автором-ботом (`forward_origin.type == "user"`
  и `sender_user.is_bot`) ДОЛЖЕН отклонить, как эмитент (03): иначе магазин узнал бы бот покупателя.
- Проверяет формат, что `plugin` платный в текущем индексе, `kid` и ключ совпадают с `shop` индекса, `blinded` —
  валидная ненулевая точка ristretto255.
- Показывает предложение (название, версия, цена, условия) с кнопкой согласия; счёт — после неё: `sendInvoice`,
  валюта `XTR`, пустой `provider_token`, одна позиция с ценой из индекса, `payload` = идентификатор заказа,
  непустой `start_parameter` (пересланная копия счёта не оплачивается).
- `pre_checkout_query`: заказ этого пользователя, не оплачен, не старше 24 ч, цена в индексе не изменилась, валюта и
  сумма совпадают. Ответ — за 10 с.
- Выдаёт лицензию **только после** `successful_payment`: `Evaluate(blinded, info)` с доказательством DLEQ и ответ
  ```
  VEILLICRES <base64url(JCS {"v": 1, "plugin": id, "kid": kid, "evaluated": base64url(32), "proof": base64url(64)})>
  ```
  Повтор того же `successful_payment` или того же `VEILLIC` после оплаты — тот же ответ без новой оплаты. Не удалось
  выдать — магазин сам возвращает оплату (`refundStarPayment`).
- Обязательные команды Telegram для платежей: `/terms` (условия) и `/paysupport` (помощь с оплатой).

### 3. Финализация (бот)
Владелец пересылает ответ своему боту. Бот проверяет доказательство DLEQ ключом магазина **из индекса** (без
проверки магазин мог бы пометить покупателя отдельным ключом) и получает `output` (64 байта). Лицензия =
(`kid`, `input`, `output`). Бот сохраняет её **до** активации: обрыв связи после оплаты лицензию не теряет.

### 4. Активация — `market.redeem` (бот → сервер)
Бот создаёт ключ установки `lic_sk` и отправляет конверт (04) с `auth.mode = "ephemeral"` — без личности:
```
op: "market.redeem"
body: {"plugin": id, "version": версия, "kid": kid, "input": b64(32), "output": b64(64), "lic_pk": b64(32)}
result: {"cert": b64(64), "key": b64(32)}
```
Сервер проверяет `output` ключом магазина `kid` (`VerifyFinalize` с `info` этого плагина), помечает
`SHA-256(input)` использованным за `lic_pk` и возвращает
`cert = Ed25519(server_sig, "veil/v1/license-cert\n" ‖ id "\n" ‖ lic_pk)` и ключ версии. Повтор с тем же `lic_pk`
— тот же ответ (обрыв связи); с другим — `E_TOKEN_SPENT`: одна лицензия — одна установка. Бот проверяет `cert`
закреплённым ключом `server_sig` и сохраняет его.

### 5. Ключи следующих версий — `market.key`
```
op: "market.key", auth.mode = "ephemeral"
body: {"plugin": id, "version": версия, "lic_pk": b64(32), "cert": b64(64),
       "proof": b64(Ed25519(lic_sk, "veil/v1/license-key\n" ‖ id "\n" version))}
result: {"key": b64(32)}
```
Сервер проверяет `cert` своим ключом и `proof` ключом `lic_pk`; база не нужна — сертификат сам подтверждает
активацию.

Обе операции бесплатные (токен не тратится, 03), на них действует общий лимит запросов. Ошибки (09):
| Код | Когда |
|---|---|
| `E_UNSUPPORTED` | маркет на сервере не настроен |
| `E_NOT_FOUND` | плагин не платный (или его нет в индексе) или у сервера нет ключа этой версии |
| `E_TOKEN_INVALID` | лицензия не от магазина (не тот ключ, не тот плагин) или неверные `cert` / `proof` |
| `E_TOKEN_SPENT` | лицензия активирована другой установкой |
| `E_MALFORMED` | поля тела |

## Что кто знает

| | знает | не знает |
|---|---|---|
| бот-магазин | Telegram ID покупателя, плагин, сумму, `blinded` | `input`, `output`, бот, личность |
| сервер (`market.redeem`/`key`) | что какая-то установка (`lic_pk`) активировала лицензию на плагин | кто платил; личность автора постов (конверт эфемерный) |
| каталог | ничего о покупателях: файлы статические | |

Слепая подпись и эфемерный конверт разрывают связь «платёж — установка». Связать их можно только по времени
(оплатил и сразу активировал) — та же оговорка, что у токенов (03, «Ограничения схемы»).

## Хранение на сервере (08)

- `market_orders`: заказ магазина — плагин, цена, `kid`, `blinded`, чат и Telegram ID покупателя,
  `telegram_payment_charge_id`, ответ, время оплаты и возврата. Неоплаченные удаляются через 24 ч; у оплаченных
  через 90 дней стираются чат, ID покупателя, `blinded` и ответ — остаются плагин, цена, время и `charge_id`
  (сводка продаж, сверка с выпиской Stars).
- `market_licenses`: `SHA-256(input)`, плагин, `lic_pk`, время активации. Без них лицензию можно было бы
  активировать много раз.

## Ограничения схемы (честно)

- **Возврат денег лицензию не отзывает**: магазин не знает, какой `output` выдал. Решение о возврате — по условиям
  магазина.
- Купленный пакет после расшифровки — обычный zip у покупателя; поделиться им или `lic_sk` с сертификатом
  технически можно. Схема защищает от установки без покупки, а не от добровольной раздачи купленного.
- Лицензия даёт ключи всех версий плагина: цена — за плагин, а не за версию.
