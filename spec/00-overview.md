# Veil Protocol v1: обзор

Статус: **черновик для утверждения** (2026-10-14). Ориентир: Telegram Bot API 10.3.

## Что это
Veil — система анонимной публикации сообщений в Telegram-группе. Участники не пишут в группу сами.
Каждый пишет **своему боту**, бот упаковывает сообщение в подписанный зашифрованный конверт
и через bot-to-bot отправляет его серверу. Сервер проверяет конверт и публикует сообщение в группе
от имени своих ботов.

Главный принцип: **анонимность держится на архитектуре и математике, а не на обещании «мы не храним»**.
Сервер по построению не получает Telegram ID человека, а то, что получает, по возможности не хранит.

## Сквозной сценарий (коротко)
```
Человек ──(Telegram)──> свой бот ──(bot-to-bot: контент + конверт)──> приёмный бот сервера
                                                                         │ проверка подписи, токена, лимитов
                                                                         ▼
                                                     очередь ──> публикующий бот ──> группа
Человек ──(Telegram, раз в неделю)──> бот-эмитент: получает анонимные токены на 7 дней
```

## Принципы, которые не обсуждаются
1. **Версия протокола в каждом конверте** (`v`). Сервер принимает текущую и предыдущую версию.
2. **Каждый конверт подписан** ключом устройства личности (пост с ником; корень личности — 12 слов — на машине
   бота не хранится) или одноразовым ключом (анонимный пост).
3. **Каждое действие оплачено токеном** (кроме чтения ленты и служебных запросов).
4. **Сервер не хранит связку «бот/человек → пост».** Право на правку и удаление доказывается секретом поста.
5. **Клиенту не доверяем.** Всё, что влияет на других (формат, лимиты, ники, вид поста), решает сервер.
6. **Telegram-специфика изолирована.** Протокол описывает конверт и операции. Транспорт (bot-to-bot)
   заменяем, если Telegram изменит правила.

## Терминология
- **Клиент**: бот пользователя (эталонная реализация `veil-client`) или общий бот.
- **Сервер**: публикатор и эмитент (код сервера закрыт, протокол открыт).
- **Приёмный бот (inbox)**: серверный бот, который принимает конверты. Их может быть несколько.
- **Публикующий бот (publisher)**: серверный бот, который пишет в группу. Их пул, очередь общая.
- **Эмитент (issuer)**: отдельный серверный бот, выдаёт токены людям.
- **Пост**: опубликованное в группе сообщение с номером `№N`. Ответ — тоже пост.

Ключевые слова «ДОЛЖЕН», «НЕ ДОЛЖЕН», «МОЖЕТ» используются в смысле RFC 2119.
