# 08. Что хранит сервер

Правило: **храним только то, без чего система не работает, и только столько, сколько нужно.**

## Хранится
| Данные | Зачем | Вид | Срок |
|---|---|---|---|
| Посты: `n`, ID сообщений в группе, `publisher_bot_id`, `kind`, `reply_to`, текст и entities, секции UPD, `post_pk`, `nick_at_post`, `id_pk` (если пост с ником), число правок, время публикации | перерисовка, правки, лента | открыто (это и так публично в группе) | пока пост существует; при удалении и при неудавшейся публикации стираются текст, автор (`id_pk`, ник, метка), `reply_to`, адресат и всё скрытое — остаются номер, вид, сообщения в группе и `post_pk` (он уникален, 05) |
| `hidden_blob` | скрытый контент | шифротекст; ключ в кнопке или у получателя | вместе с постом |
| `hidden_key_enc` | заново прикреплять кнопку «Показать» при правках (07) | `K`, зашифрованный ключом из секретов | вместе с постом; стирается при удалении |
| `hidden_to_label` | строка «лично для Петя·k2m9xq — прочитать может только он» | открыто (видно в группе) | вместе с постом |
| Личности: `id_pk`, метка, ник и его ключи похожести, действующий сертификат устройства (`dev_pk`, `seq`, `dev_sig`), ключ шифрования (`enc_pk`, `exp`, `enc_sig`), время смены ника и ключа | ники, `nick.lookup`, проверка устройства | открыто (публичные ключи и подписи) | бессрочно; прежние устройства и ключи шифрования не хранятся |
| `bind_hash = HMAC(pepper, bot_id)`, время привязки | «один бот — один ключ» | HMAC | пока личность привязана |
| Потраченные токены `SHA-256(kid‖day‖input)` и `id` конверта, который их потратил | двойная трата, однократность повтора | хеш | до конца дня; партиции по дням удаляются целиком |
| Счётчики эмитента `HMAC(pepper, "veil/v1/issuer-counter\n" ‖ user_id), day, issued` | лимит 50/день | HMAC | до конца дня, на который выдано |
| ID операций (`envelope.id`) | защита от повтора | открыто | 24 ч |
| Очередь отправки (outbox), у правок и удалений — `id` конверта | надёжная публикация, однократность повтора | открыто | до успешной отправки + 24 ч |
| Заказы бота-магазина (10): плагин, цена, `kid`, `blinded`, чат и Telegram ID покупателя, `telegram_payment_charge_id`, ответ, время оплаты и возврата | счёт в Stars, повтор ответа, возврат | открыто | неоплаченные — 24 ч; у оплаченных через 90 дней стираются чат, ID покупателя, `blinded` и ответ (остаются плагин, цена, время, `charge_id` — сводка продаж и сверка с выпиской Stars) |
| Активированные лицензии (10): `SHA-256(input)`, плагин, `lic_pk`, время | одна лицензия — одна установка | хеш и публичный ключ | бессрочно |

## НЕ хранится
- Telegram ID людей (кроме HMAC-счётчиков эмитента с суточным сроком и заказов бота-магазина плагинов: ID
  покупателя нужен для возврата Stars и стирается через 90 дней после оплаты, 10).
- ID ботов пользователей у постов. ID бота-отправителя используется только в момент обработки
  и для лимита запросов в памяти.
- Расшифрованные конверты и их содержимое в логах.
- `K` скрытого контента «для всех» в открытом виде (только зашифрованным, см. выше).
- Кто нажимал «Показать» и кто запрашивал ленту.

## Логи
- Уровень по умолчанию: коды ошибок, длительность, `op`. Без ID ботов, без Telegram ID, без текста, без номеров
  постов рядом со сбоями (журнал не связывает посты со сбоями ключей и удалением).
- Отладочный режим, который логирует больше, включается только флагом запуска и пишет предупреждение
  в канал админа.

## Секреты вне базы
Ключи сервера (подпись ответов, приём конвертов, эмитент, магазин плагинов), «перец» для HMAC и ключ, которым
зашифрован `K` скрытого «для всех», хранятся отдельно от базы. Поэтому одна база (или её копия) без них не раскрывает
ни привязку ботов (`bind_hash`), ни счётчики эмитента, ни скрытый контент.

## Откат базы
Если базу восстановили из старой копии, у личностей могут вернуться прежние устройства и ключи шифрования, а у токенов —
статус «не потрачен». Последствия ограничены:
- устройства и ключи: бот владельца при первой же операции получает `E_DEVICE` или видит в `device.get` старый
  `seq` и сам повторяет `device.set` своим сертификатом (`seq` больше) — отозванное устройство снова отзывается;
  отправители, уже видевшие больший `seq`, откат замечают (02);
- токены: потраченные после снятия копии можно потратить ещё раз только в тот же день (токен действует один день);
- повторы конвертов: окно `ts` ±300 с, поэтому старые конверты не проходят, даже если `replay_ids` откатились.

## Расширяемость
У постов уже есть `chat_id`, хотя группа одна: это позволит подключить несколько групп без смены протокола.
